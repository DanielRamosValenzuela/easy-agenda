# Implementation Plan: Sitio Completo EasyAgenda — Landing, Páginas y Reservas

**Branch**: `001-landing-booking-site` | **Date**: 2026-02-26 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/001-landing-booking-site/spec.md`

## Summary

Construir el sitio completo de EasyAgenda con landing page (hero + búsqueda centralizada),
exploración de clubes y canchas, flujo de reserva con calendario, página de precios,
contacto y dashboard de usuario. Todo con datos dummy estáticos. La arquitectura sigue
Feature-Sliced Design (FSD) con Next.js 16 App Router, shadcn/ui y Tailwind CSS v4.
El diseño de referencia es EasyCancha (easycancha.com/es-CL).

## Technical Context

**Language/Version**: TypeScript 5 (strict mode)
**Primary Dependencies**: Next.js 16.1.6, React 19.2.3, shadcn/ui (new-york), Tailwind CSS v4
**Storage**: N/A (dummy data as TypeScript constants)
**Testing**: Manual verification via quickstart.md (no automated tests for this iteration)
**Target Platform**: Web — modern evergreen browsers (Chrome, Edge, Safari, Firefox)
**Project Type**: Web application (Next.js App Router, SSR/SSG)
**Performance Goals**: LCP < 2.5s, FID < 100ms, CLS < 0.1 (Core Web Vitals)
**Constraints**: Responsive 320px–1920px, Spanish-first UI, CLP currency
**Scale/Scope**: ~10 pages, 8 entities, ~15 widgets, ~3 features, ~7 entity slices

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

| Principle | Status | Evidence |
|-----------|--------|----------|
| I. FSD Architecture (NON-NEGOTIABLE) | PASS | All code organized in `src/` with FSD layers: app, pages, widgets, features, entities, shared. Strict unidirectional imports. Public API via `index.ts`. |
| II. Server Components First | PASS | Widgets default to Server Components. Only components requiring state/events marked as Client (`"use client"`): Navbar (mobile menu), HeroSearch, StatsCounter, CourtCatalog, CourtDetailView, BookingForm, ContactForm, SearchBar. |
| III. Type Safety (NON-NEGOTIABLE) | PASS | All entities have TypeScript interfaces. Zod schemas for form validation (booking, contact). No `any` types. |
| IV. Simplicity & YAGNI | PASS | No database, no auth, no payments. Dummy data as constants. CSS-only scroll animations. Minimal dependencies. |
| V. Public API Boundaries | PASS | Every FSD slice exposes `index.ts`. shadcn/ui in `shared/ui/`. No cross-slice imports at same layer. |
| VI. Spanish-First UI | PASS | All user-facing text in Spanish. Technical identifiers in English. CLP currency confirmed. |

**Gate result**: ALL PASS — proceed with implementation.

## Dependencies to Install

| Package | Via | Purpose |
|---------|-----|---------|
| shadcn/ui init | `npx shadcn@latest init` | Base setup: cva, clsx, tailwind-merge, lucide-react, tw-animate-css |
| calendar + popover | `npx shadcn@latest add calendar popover` | Calendar component: react-day-picker, date-fns |
| form + input + label | `npx shadcn@latest add form input label` | Form handling: react-hook-form, zod, @hookform/resolvers |
| button, card, dialog, select, separator, badge | `npx shadcn@latest add ...` | UI primitives |

**No additional npm packages needed.** All dependencies come through shadcn/ui.
Scroll animations are CSS-only (no JS library).
